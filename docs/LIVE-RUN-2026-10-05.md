# Live run — 2026-10-05

What one human session against the **live `hotelSystem`** database exercised, and what it
did not. Written the day the run happened so the record is not reconstructed from memory.

## Setup

- Business date: 2026-10-04 (set in `HotelSettings`; a clock, not a night audit —
  `docs/DEVIATIONS.md` §3).
- Test guest: last name `test`, first name `123`, customer profile 2.
- Room 10001 (Standard), booking desk booking with a prepayment at booking time.
- All steps ran through the normal console UI (`python main.py`), no direct SQL.

## Paths exercised (all observed working)

| Path | Observed result |
|---|---|
| Customer check-in | Room marked `Occupied`, key card `KC-330851` issued, profile linked |
| F&B order to room bill | `Hot Chocolate` item 7, $90.00, added to bill, not paid inline |
| Check-out with prepayment credit | Room charge `1 night(s) x $120.00 (Standard)`, credit `-$135.60` applied, tax 13% on $210, balance $101.70 charged on card `5555...4444`, invoice recorded, no double charge |
| Loyalty accrual | 45 order points (`90.00 × 0.5 × tier x1.00`) **and** 100 stay points (`1 night × 100/night × Standard ×1.00 × tier x1.00`), both attributed to customer 2 |
| Out-of-window reservation (room 10002) | Under the old code: warning printed, check-in proceeded. **Code since changed (f70f0ec): check-in now refuses.** That warning sighting is the evidence for the change. |

## Invariants observed

- Room charge posted exactly once per stay (the `post_room_charge()` once-only guard held
  across the whole check-out).
- Prepayment credit applied after loyalty, before the balance-due prompt.
- Loyalty points keyed on the customer, not the room.
- No `Items` row named "Room Charge"; the room charge is a `Transactions` row with
  `ItemID` NULL and `ChargeGroup='Room'`.

## Paths NOT exercised live (still e2e-only or unverified)

- Booking cancellation and the refund paths (`cancel_booking()`, `refund_decision()`).
- A declined card at check-out, a redemption with insufficient points, a double check-out.
- `BookingRefTaken` against the live unique index.
- The 019–021 flows beyond catalog shape (customer identity resolution by email, booking
  reference collision, captured-rate backfill of old rows).
- Any interrupted `check_out()` — resumability is measured only in `verify_e2e.py` Phase 5b.

## Code changes that shipped the same day, each now load-bearing

- `f70f0ec` — check-in **refuses** when the business date falls outside the reservation's
  window (was: warn and proceed). Window predicate: `CheckInDate <= today < CheckOutDate`,
  half-open, same convention as `docs/DEVIATIONS.md` §6.
- `7b13f72` — every menu loop pauses ("Press any key") before redrawing its menu, and the
  main loop pauses before `ui.clear_screen()`.
- `e829935` — Customer and Bookings menus' exit entries are now **Sign Out**, clearing
  `CURRENT_CUSTOMER`.

## What would make this stale

- The reservation used for the room-10002 observation is still live with dates that do not
  match the business date; it should be cancelled or corrected, otherwise the live DB
  carries a knowingly-wrong stay.
- `check_applied_migrations.py` had not been re-run after the stay at the time of writing;
  re-run it.
